# 2026-09-21 — Vocabulario del producto para quien lleva el negocio

## Recursos

Se instaló el worktree con `npm ci --prefer-offline`. Se ejecutó el test de vocabulario antes del cambio y falló. Después de dejarlo verde, se creó temporalmente una etiqueta visible «PyME»; el mismo test falló con `src/vocabulario-prueba-temporal.tsx:1` y el archivo temporal se eliminó. La primera corrida E2E completa dio 132 pasados, 2 salteados y 2 fallos en Mobile Safari: uno registró errores de recarga de Vite mientras se editaba un archivo y otro agotó tiempo sobre un botón que se desmontaba. Los dos specs fallidos pasaron aislados (5/5), y la segunda corrida completa con el árbol estable pasó 134/134, con 2 salteados. No se estimaron tokens.

## Qué se hizo

Se reescribieron los textos visibles que usaban «costista», «empresa» o «PyME» en las pantallas del frontend. El test AST recorre literales y nodos JSX del código de producción e informa archivo y línea. El mismo vocabulario se comprueba con Playwright en login, home, panel de campo y tablero del dueño. El barrido equivalente sobre `origin/dev` encontró **95 fragmentos visibles en 38 archivos**; después del cambio encontró **0**.

## Decisiones que tomé sobre la marcha

- **Qué decidí:** usar «negocio» para la entidad y reescribir las frases para que mantengan concordancia. **Qué otra opción había:** sustituir palabras literalmente sin ajustar la oración. **Por qué elegí esta:** la persona debe poder leer instrucciones naturales sin jerga (Constitución §1).
- **Qué decidí:** usar «Mi cuenta» o describir la acción de revisar en lugar de inventar un nombre de rol nuevo. **Qué otra opción había:** mostrar `EMPRESA_ADMIN` o anticipar una etiqueta de rol que el backend aún no entrega. **Por qué elegí esta:** la decisión técnica de roles no equivale a una etiqueta pública acordada (Constitución §2 y §9).
- **Qué decidí:** conservar nombres de campos, rutas, enums, `sourceArea` y valores `origen` en sus contratos. **Qué otra opción había:** renombrarlos junto con el texto. **Por qué elegí esta:** #187 los deja fuera de alcance; alterarlos rompería integraciones (Constitución §8).
- **Qué decidí:** comprobar sólo texto de interfaz producido por el frontend en el test AST y el texto visible de los cuatro recorridos E2E con respuestas sintéticas. **Qué otra opción había:** prohibir también nombres ingresados por personas y valores técnicos recibidos de la API. **Por qué elegí esta:** el frontend no puede cambiar esos datos sin falsearlos (Constitución §2 y §4).
- **Qué decidí:** para la ayuda de IVA, expresar el criterio de la cátedra en paráfrasis. **Qué otra opción había:** cambiar una palabra dentro de la cita entre comillas y presentarla como literal. **Por qué elegí esta:** una cita modificada atribuiría palabras inexactas a la fuente (Constitución §2).

## Dónde el issue no alcanzaba

- No definía una etiqueta pública para el rol que reemplazará a `COSTISTA`; se evitó mostrar un rol nuevo.
- No distinguía el vocabulario escrito por el producto de nombres propios cargados por quien usa el sistema ni de textos de API. El test está acotado a texto del frontend y los datos sintéticos E2E no usan términos prohibidos en los cuatro recorridos requeridos.
- No especificaba cómo detectar cadenas dentro de TypeScript sin marcar rutas, enums, claves de persistencia ni campos de contrato; se usó el AST con exclusiones técnicas explícitas.

## Qué quedó afuera

- No se renombraron identificadores ni contratos técnicos, según el alcance de #187.
- El backend aún genera textos dirigidos a personas con ese vocabulario. Se abrió [backend #409](https://github.com/Coste-AR/CosteAR-backend/issues/409) con los casos confirmados de correo, catálogo y asesor; este PR no los modifica.
